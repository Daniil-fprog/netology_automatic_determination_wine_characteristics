# Мониторинг

## Технические метрики

Endpoint `/metrics` публикует количество запросов, ошибок, прогнозов, суммарную задержку и состояние загрузки модели. На уровне платформы также следует собирать p50/p95/p99 latency, CPU, RAM, число рестартов и долю ответов `4xx/5xx`.

Рекомендуемые алерты: `/health` недоступен 2 минуты, доля `5xx` выше 2% за 5 минут, p95 выше 500 мс, резкий рост `422`, отсутствие трафика при ожидаемой нагрузке.

## Качество и дрейф

Без сохранения исходного текста логируются: длина описания, доля пустых наборов нот, распределения предсказанных классов, средняя уверенность, версия модели и хэш таксономии. Это позволяет отслеживать input/prediction drift без записи чувствительного текста.

После появления отложенной ручной разметки рассчитываются macro-F1 для категориальных целей и micro-/macro-F1 для мультиметок. Переобучение запускается при статистически значимом дрейфе либо падении ключевой метрики ниже согласованного порога.

Важно отдельно мониторить режим `model_mode`. Для текущего bundle ожидается `supervised`, при этом источник целей должен быть явно обозначен как LLM-псевдоразметка. Неожиданное изменение режима должно вызывать алерт и блокировать автоматическое продвижение версии.
