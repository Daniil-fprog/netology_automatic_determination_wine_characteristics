# Архитектура решения

## Поток обучения

1. `data/wines_annotated.csv` загружается и проходит аудит схемы, пропусков и дубликатов.
2. Название, описание и рекомендации объединяются и нормализуются.
3. Для обучения используется частичная LLM-псевдоразметка. Категориальные модели обучаются на строках, где заполнена соответствующая цель; для мультиметочных целей используются все доступные размеченные строки. Bundle работает в режиме `supervised`, но метки не считаются экспертной истиной.
4. Текст преобразуется в символьные TF–IDF n-граммы длиной 3–5.
5. Для четырёх категориальных целей обучаются независимые логистические регрессии.
6. Для каждой допустимой ароматической и вкусовой ноты обучается отдельный бинарный классификатор.
7. Модели, векторизатор, кодировщики, пороги и метаданные сохраняются одним `joblib`-bundle.

## Поток инференса

`HTTP request → Pydantic validation → text normalization → TF–IDF → classifiers → JSON response`

```mermaid
flowchart LR
    C[Клиент] --> A[FastAPI]
    A --> V[Pydantic validation]
    V --> P[WinePredictor]
    P --> T[TF–IDF]
    T --> C1[4 categorical classifiers]
    T --> C2[Multi-label classifiers]
    C1 --> R[JSON response]
    C2 --> R
    A --> M[/metrics]
```

FastAPI загружает bundle один раз при старте. Пакет `wine_characteristics.predictor` не зависит от HTTP и может использоваться отдельно в batch-задачах.

## Принятые решения

- TF–IDF выбран как быстрый и интерпретируемый baseline для русского текста без GPU.
- Независимые классификаторы упрощают обновление таксономии и диагностику отдельных целей.
- Модель не использует цену, страну и прочие каталожные поля, чтобы контракт оставался текстовым и не возникала утечка бизнес-признаков.
- LLM-разметка позволяет проверить полный supervised-контур, но метрики отражают согласие модели с псевдоразметкой. Для оценки реального качества нужны ручная экспертная разметка и независимый test-набор.
